## Main conclusion

The software already has substantial functional breadth and valuable safeguards: shared desktop/thin-client workflows, explicit workspace context, immutable datasets/builds/releases, review-before-save, controlled reference-system execution, bounded previews and deterministic tests. The largest opportunities are reducing demonstrable read/observer amplification and establishing current quality/user evidence. A static review does not establish that a declared performance target is missed.

The proposed order is navigation/composition, background tasks, Context allocation, then controlled user/model qualification. The first three deliver independently useful behavior and can roll back separately; the final increment crosses a real hardware, assistive-technology and representative-user qualification boundary. Measurement and probes stay with their first useful consumers, avoiding an isolated instrumentation-only increment.

The configured runner requires trusted probes; a repository-owned production-path probe set was not located. No current before/after result was established by this review.

New page, request-reduction, allocation, throughput, retrieval-quality and usability numbers in the matrix are proposed acceptance targets. Approving the roadmap adopts them for the named representative fixtures/profiles; they are not measured baselines or production promises. Preserve correctness/security as hard gates. Before optimizing, record the unchanged candidate with source/product/environment, exact fixture/model identity, workload, warm/cold definition, sample count and failure denominator. Report uncertainty and unavailable measurements. Use actual RSS and production-path probes; unit-test duration and provider mocks do not qualify performance or model quality.

## Security impact

Security-relevant proposed implementation affects authorized summaries, task ownership/resource lifecycle and untrusted Context bytes. Preserve authoritative organization/workspace scoping, immutable identities, all integrity/vector/citation checks, bounded execution/observation, explicit installed-model authority, private cleanup and sanitized evidence. Prove cross-workspace/unauthorized/stale/malformed/failure/cancel paths. Rollbacks retain stronger security controls. Hardware/model/assistive-technology and existing residual security qualification remain pending.
