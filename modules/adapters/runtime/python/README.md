# Python runtime adapter

## Private protected training source copy

The original Windows controller has a private, default-off source-copy owner.
Trusted composition must supply a complete safe-format manifest, current source
authority and an existing measured storage reservation. It creates only a fresh
directory, opens source files by native parent handle, checks hashes, copies and
rehashes bytes, then seals private permissions with an OWNER_RIGHTS restriction.
Read guards and read-only duplicate handles precede app process creation.
The initial descriptor already denies foreign control and metadata writes and
suppresses implicit owner DAC access. Only positively attested original creator
handles may mutate the copy; no later mutable pathname open is used. If those
creator rights are not granted, preparation fails closed.
Stop and input closure are observed during preparation. Closing the original
worker does not remove the copy or free its disk reservation: positive retained
accounting is a separate requirement. Candidate output has a separate owner.

This is a producer/controller component. Ordinary v1 BOOT and production roots
do not configure it. The original Node authority/reservation channel, inherited
bootstrap, worker-side lease and full input/output producer remain pending.
Synthetic native-API tests do not qualify physical Windows behavior, an installed
runtime, hard storage limits, real training or the parent roadmap.

The foundation captures model-cache configuration once for both hosts, in the
order `HF_HUB_CACHE`, `HUGGINGFACE_HUB_CACHE`, `TRANSFORMERS_CACHE`, then existing
home/default resolution. Explicit relative roots still fail. Its trusted
configuration factory grants no worker start or filesystem access. An accepted
source returns a frozen original-controller result handle with exact task,
workspace, repository, pin and manifest identity. Captured read/cancel/completion
methods do not look up a reusable shared-history ID. Shared caches update only
while that same original entry remains; completed original outcomes survive
history eviction without changing a later task with the same ID.
Generic read, cancellation and completion refuse approved-source/preparing IDs;
generic listing excludes them before refresh and output. Only their original
captured handle can advance the source controller. The Worker also refuses
generic cancellation before touching a source Future, including a delayed old
request. Exact bound source cancellation remains available.

The internal `ApprovedModelSourceDownloadPort` connects a captured source job to
the existing accepted Model Task owner. It has no default configuration and uses
explicit installed-only preparation; missing support never selects the ordinary
installer or SDK path. Copy exact source/workspace/limits and separate trusted
host/business controls before awaits. These callbacks are not user approval.
Ordinary starts reserve the same tracker before POST and compare that original
reservation before publishing a late ACK; an old reply cannot replace source
custody, even after terminal-cache rotation.

The original `acceptedModelDownloads` entry retains its actual controller and
receiver before effects. The foundation's existing task tracker retains at most
one unsettled source acquisition, matching the worker stage slot. History rotation,
sibling timeout/cancellation and even actual worker exit cannot erase that
custody. Protected capacity denies new work before preparation/dispatch. Confirmed
settlement restores ordinary recovery policy; source admission installs nothing.

Worker success is not stored Model completion. The owner verifies its closed
receipt and sender cleanup, consumes the receiver once through the existing
generated-model storage port, and verifies the exact original repository/pin
destination, complete inventory and bounded closed file hashes/identities. Only
known Node retirement and separate receiver-settled acknowledgement publish the
private completion.
Storage invocation and final completion each recheck original business permission
in their effect continuation. A final denial withholds completion and further
import while retaining the positive facts of already confirmed cleanup.
Captured reads and exact ACK replay may resolve lost replies; download, import
and native cleanup are never repeated. A positively bound
cancelled/failed empty job may retire only its own known empty receiver. Unknown
start, IO, publication or close retains custody and grants no adoption or retry.
The storage checks retain the existing cooperative filesystem boundary; they do
not establish native hostile-writer fencing or restart durability. Public plan
admission, original actor permission, Model registration and actual app/model
qualification remain separate I7 work.

An issued reservation repeats business admission after preparation and carries

An exact accepted start binds a private job handle to task, acquisition, handoff,

## Explicit bounded offload

close retains the cache owner. Model unload does not reset process-global CUDA
library state; qualification records initialized runtime floors separately from

before tokenizer/model reads; unsupported local adapters cannot redirect sources.

and bounded numeric diagnostics; they never become format failures or poison an
unstarted forward. Placement and execution reserve checks remain unchanged.

deleted. See `docs/operations/optional-low-memory-inference.md` for finite limits,

## Memory admission notifications
